# V2 · 模块 09.4：本机存储诊断与受损草稿保护

**仅开发分支和 draft PR #1；正式网站、线上 Supabase 不受影响。** 本子模块的“完成”指代码、自动测试和文档通过，不是手机真机验收。

## 本模块已实现

- 用户可以在“本机加密草稿”面板手动点击「检查本机存储」：对 IndexedDB 进行一次 **同一 readwrite 事务内临时写入并删除** 的检查。临时记录是随机编号，不包括任何账号信息、文字或口令；如果事务失败，则明确提示不要依赖本机备份。
- 如果浏览器提供 `navigator.storage.persisted()`，显示当前数据保留模式；如果提供 `navigator.storage.estimate()`，展示**站点整体**使用量估算比例（不是队列实际占用，也不是精确磁盘容量）。当估算占用达到 85% 时提示空间风险。
- 用户可以主动点击「申请减少浏览器自动清理」。浏览器通过 `navigator.storage.persist()` 决定是否授予，拒绝/不支持不被当作成功。**不在页面加载时自动申请权限**。
- 新增密文记录元数据检查：如果 IndexedDB 某一条密文格式明显受损，列表会标注异常，允许用户手动二次确认清除；**其它完整草稿仍可单独恢复**，不会因坏一条而自动删除整组。若账号/书房/操作编号等身份元数据不一致，整组停止处理以防错误归属。
- 原有 AES-GCM 解密/认证仍然是恢复正文的唯一途径。密文结构检查**不能证明密码正确或数据完整**，也不能修复已损坏的加密内容。
- 保留旧版 localStorage 备份和 IndexedDB 草稿，不进行自动迁移、自动上传或自动清理。

## 测试与边界

- `tests/unit/storageHealth.test.mjs` 验证正常与失败写入检查、缺失 API、持久化同意/拒绝、容量估算异常以及只有主动调用才申请持久化。
- `tests/unit/atomicPending.test.mjs` 增加受损密文隔离、正常草稿读回和错误归属阻断检查。
- GitHub Actions 同时运行此前的数据库 RLS/审计、加密单测、TypeScript、严格 ESLint 和 Next.js 静态构建。
- **未进行真实手机 Safari/Chrome 的 IndexedDB 事务与设备休眠/强制结束 App 测试。** 持久化授予不等于无限保存：网站数据清除、应用卸载、系统清理、断电、硬件故障仍可能丢失密文；没有实现跨设备同步。
