## 本次完整交付的功能

1. **双人在线活跃提示。** 在书房面板显示伙伴是否加入、近 90 秒是否有已认证心跳；30 秒可见页面心跳，20 秒服务端去重，60 秒可见页面的回退轮询；切换房间、用户、卸载组件后取消通道和旧请求。它不是精确的在线/已读回执。
2. **共享内容自动刷新。** 数据库可信触发器对共享批注、共享手绘及共享回复的变化增加每房间单调版本号；前端只订阅经过 RLS 限制的 `reading_shared_signal_v2`，接到通知后重新查询当前已打开页面的批注、手绘和已展开的回复，断线通过可见时轮询/回焦恢复。不推送全文、引文、笔记 ID、章节、页码、隐私备注或作者 ID。
3. **服务端防剧透。** 独立 `reading_spoiler_frontier_v2` 记录每个成员明确打开过的最大段落，更新只可单调前进。读取书籍段落成功后调用受保护的 `v2_acknowledge_read_chunk`；宽屏后来载入的右页也需先登记。RLS 在**直接 PostgREST 表 SELECT** 层拒绝提前读取其他成员的未来共享批注、未来共享手绘与未来批注回复。对本人笔记仍有访问权；旧版无定位的 `reading_notes_v2` 只给本人看。
4. **防止绕过前端。** 双人房成员凭 `auth.uid()` 和当前活动成员状态授予读权限；离开、关闭的房间及陌生账号服务端拒绝看到共享信号/未来内容。回复创建还由服务器插入触发器重复验证分享原文权限，防止用已知笔记 UUID 通过 SECURITY DEFINER RPC 越过阅读位置限制。
5. **独立阅读进度。** 实时事件完全不改变自己的阅读位置和书签；沿用模块 08 的 Unicode 码点坐标和版本 CAS，不把伙伴进度作为同伴状态广播载荷。浏览过后回退不会把已解锁的页面重新隐藏。
6. **无新费用、无生产更改。** SQL 全部写在新 V2 migration；现有用户数据、旧表、`main` 和生产 Supabase 均未变更，PR #1 仍为 draft。无新增付费服务、前端密钥或第三方正文传输。

## 明确保留的边界和下一阶段阻断项

- **真实 staging 不可替代**：必须在与正式库不同的 Supabase 项目按文件名顺序安装 migration，并在两组真实账号、两个设备上验证 Realtime publication/RLS、失联重连、iOS Safari 与 Android Chrome。CI 的 PostgreSQL 无 Supabase WebSocket，因此并不声称已经跑过真实双人 WebSocket/手机测试。
- **防剧透不是 DRM**：合法房间成员本来有权通过受保护读取接口主动打开未来正文；这属于用户自主阅读，浏览器不可彻底阻止主动复制、截图或从有权访问的文本中理解情节。服务器只阻断未经主动开启的**共享批注/回复/手绘**过早泄露。
- **通知只是无内容事件**：`updated_at` 及消息到达时间仍可能暴露房间内有某次共享活动，不能推断具体内容，且不被用于保证消息实时送达；不可宣称真正“绝对隐身”或“毫秒在线”。
- **内容视图缓存**：服务端成员撤销会拒绝后续查询，但已显示在对方设备的字句/截图无法远程擦除；前端重新鉴权的完整端到端收口将在模块 12/14 验证。
- **不是独立信息流/陌生人社交**：书房发现、举报及屏蔽仍属模块 11；导出删除属模块 12；跨账号滥用防护和独立安全审计属模块 13。

验收口径：**模块 10 的代码功能与 CI 自动检查通过，工程覆盖可以记为 100%；生产上线、真实多端端到端准备度不据此提高或宣布完成。**
