# V2 · 模块 09.3：IndexedDB 加密草稿持久化

**开发分支测试代码，未部署。** 本子模块是 14 个一级模块中第 09 模块的一部分；通过不代表整个离线同步模块完成。

## 这轮新增

- IndexedDB 原子对象存储：每条草稿使用独立记录，索引按账号、书房和内容位置的哈希隔离；数据库事务内进行重复发送编号检查、容量检查、写入。避免以前 localStorage 多步写入索引时因崩溃留下不一致记录。
- 沿用 AES-GCM 加密：保存随机发送编号和加密信封，不保存正文、可见范围、被选中的原文或解锁口令明文。
- 每个目标最多 10 条，逐条解密、恢复、二次确认删除；恢复后需要用户明确点击发送。服务端成功确认后仅清除对应 UUID 的密文。
- 旧版 localStorage 多条队列与单条备份仍保留恢复入口，不自动迁移也不自动删除。
- 不支持或无法访问 IndexedDB 时失败并提示，不偷偷转用不安全的明文缓存。
- 浏览器重新打开阅读页时可重新列出 IndexedDB 密文；没有口令无法解开。

## 自动测试与边界

单元测试 tests/unit/atomicPending.test.mjs 用模拟原子数据库测试：并发插入、重新创建访问对象以模拟重启、跨账号隔离、限制 10 条、重复 UUID 拒绝、篡改密文阻断。GitHub Actions 还验证严格 ESLint、TypeScript/Next.js 静态构建与隔离 PostgreSQL 权限。

这些测试没有执行真实浏览器 IndexedDB 驱动的 UI 端到端流程；尚未在 iOS Safari、安卓 Chrome、多个真实标签页上验收。IndexedDB 事务原子性不代表断电后保证落盘；用户清理网站数据、无痕模式、磁盘损坏仍可能丢失密文。当前依旧没有跨设备自动同步，也不会联网自动上传私人草稿。

旧版 localStorage 队列仍依赖 Web Locks 保护并发；新 IndexedDB 队列无需 Web Locks。
