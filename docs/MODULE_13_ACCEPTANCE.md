# 一级模块 13｜安全、版权及独立审计接口：代码验收

**状态：开发分支代码与隔离自动测试的限定验收。没有真实外部机构审计、没有独立生产锚定，也未通过法律版权合规审查。**

## 本模块已实现的代码功能

1. **上传版权声明的后端拦截**：只有房主可向服务器明确选择原创、公有领域或已有授权。新版 `reading_chunks_v2` INSERT 触发器在服务端校验权利声明，未确认时拒绝写入；TXT、EPUB、PDF 导入和短文本测试上传同时禁用未确认入口。原有书籍不会因安装迁移而自动获得法律版权证明。声明只代表用户提供的说明。
2. **版权留痕**：单独受限表保存房主当前声明，另以仅服务端可写的历史表记录每次声明/修改及时间；对匿名、其他成员和普通客户端拒绝查询或伪造版权凭证。
3. **举报受控处理**：举报人通过受保护 RPC 查询仅属于自己的投诉编号、理由和进度。受信审核人由平台运营者在线下可信 SQL 单独授权；不能自行注册成审核人。审核队列返回举报所需信息，不返回书籍或私人批注。pending → reviewed → closed 的受控流转，处理理由与审核人记入客户端不可直接写改的记录。
4. **数据库内审计链核对**：历史书房成员可调用 `v2_verify_room_audit` 获取链是否完整、核验条数及最后摘要；验证每一条的次序、前一摘要和规范化事件 SHA-256，检测隔离测试中对事件摘要的篡改。不公开原始私人笔记和正文。
5. **供独立审查的可验证证据**：只有预授权审核人可以按游标、小批次导出规范化、无正文的审计事件。Node 离线脚本核对 SHA-256 链，持有线下保管的 Ed25519 私钥的一方才能给链头签署独立收据；用预先可信固定的公钥核验收据。私钥、真实签名收据和审计事件材料都不得提交公开代码仓库。签名必须被独立保存才具备对数据库被重写的额外发现价值。
6. **UI 安全可见性**：阅读器区分原创、公有领域、已有授权三种声明；登录大厅可查看自己的举报状态、受信审核案件操作入口与书房审计检查结果，明确注明数据库哈希校验不等于真实外部审计。

## 验收与隔离

- `tests/sql/reading_security_v2_smoke.sql` 从最初的身份隔离、两人房间到模块 12 完整测试迁移，覆盖未确认上传拒绝、房主声明、非房主不能冒认、未经授权不能读取版权/举报/审核数据、受信审核人唯一权限、案件进度与审核留痕、正常哈希链与篡改检测、审核证据分页、匿名限制。
- `tests/unit/auditProof.test.mjs` 用**仅测试时临时生成的**签名密钥校验独立收据，测试内容修改、掉记录、伪造签名、伪造房间号都会失败；私钥不提交、不复用。
- CI 继续跑严格 ESLint、Next.js 静态构建、全量 Node 单元测试、Chromium 真实浏览器回归和 PostgreSQL 16 数据库权限测试。
- 所有更改仅在 `feat/phase0-foundation-2026-10-18` 与草稿 PR #1。正式 `main`、旧版 Supabase、备份不改动。

## 尚不能宣称的事情

**尚未实际委托第三方审计，也没有建立运营中的独立锚定存储。** 两个签名脚本只是可供将来执行的工具，不能证明曾有外部机构签署。审核账号仍需运营方独立任命；没有实际工作人员、案件 SLA、申诉机制或有效的跨账号/IP/设备限流与风险评估。版权声明不等于真实版权许可，不能代替侵权下架通知、争议处理或法律判断。合法获权读者仍可能复制已展示文本。真实多账号 Supabase、手机安全、备份保存/销毁及生产级完整独立安全评估均待后续上线验收。

**工程进度口径**：模块 13 的约定应用代码、服务端校验及离线独立核验工具可按 100%（限定代码/自动测试）记录；实际外部审计与安全运营严格保持“未完成”。正式上线准备度不据此提高。
