# 一级模块 04 · 书籍导入与本地格式解析（TXT / EPUB / PDF）

**交付范围：开发分支中的安全、纯文字 V2 阅读预览。正式发布前必须经过第 14 模块真实手机与 staging 账号验收。**

本模块按 14 个一级模块的计划统一验收，不把 TXT、EPUB、PDF 单独当作三次交付，也不自动上传用户打开的私人文件。

## 已实现的完整导入流程

1. **本地解析并预览**：房主选择文件后，只在当前浏览器内解码，先展示总 Unicode 字符数、分段数、识别到的章节、逐段预览及章节导航。没有上传权限的读者不会看到上传入口。必须主动勾选版权及上传确认，才能把提取后的文字发给受保护的独立 V2 测试书房。
2. **TXT**：支持 UTF-8（含 BOM）和 GB18030 / GBK；保留空行，统一 Windows / Mac 换行。按 Unicode 码点分段，每段最多 2800 字（数据库上限 3000），不切坏中文/emoji 代理项；识别中文“第 N 章”等标题与英文 Chapter。拒绝空文本、非法编码、嵌入 NUL、伪装二进制的危险控制字符与超量文件。
3. **EPUB**：在浏览器本地读取 EPUB ZIP/OCF，校验 ZIP 文件目录、路径穿越、重复文件名、压缩类型、尺寸上限和 CRC；阻止 ZIP 炸弹及解压超限。检查 mimetype、container、OPF manifest/spine，仅提取安全 XHTML 的文本和章节，不执行脚本、不加载图片或外部资源；拒绝检测到的 DRM/加密或无法解析的章节。
4. **PDF**：集成固定版本 Mozilla PDF.js 的浏览器内工作线程，提取**具有文字层**的 PDF 页面，按页次序转换为可预览的纯文字和“PDF 第 N 页”章节目录。必须以本地 Uint8Array 作为输入，不会发文件 URL 给第三方；禁用动态 JavaScript eval。明确拒绝空白/扫描版无文字层、不可解析的损坏文件和部分加密 PDF。最多 10 MB、120 页、100 万 Unicode 字符。**此功能不是 PDF OCR，也不保留 PDF 排版、插图或表格几何。**
5. **上传权限**：独立测试数据库的受信 RPC 只允许有效书房房主上传；普通成员、陌生账号、匿名账号及已关闭书房均被拒绝。每段原文只能首次写入，任何后续更改都被拒绝；数据库禁止普通客户端直接读取正文表或更改上传配额。
6. **安全恢复**：本次新增 \`v2_upload_book_chunk_retry\`，在数据库锁和作者验证内比较已有段落。上传成功但网络断线导致客户端没有收到确认时，重复发送**完全相同**文字返回 already_saved，不再二次计费；原文不同返回 conflict 并保留原段落。每用户每天总计上限 300 个新增段落，可在收到服务器确认后继续未完成的部分。
7. **章节登记与冲突保护**：所有段落确认上传后，才登记不允许更改的章节标题与开始位置。用户可以选择上传起始段落与首次目录编号（各自独立），最多 2000 段、200 章节。章节写入失败不需要重复上传正文；原章节一致时可重试，不同元数据拒绝覆盖。还没有启用书籍替换或在线增量编辑。
8. **资源与隐私边界**：TXT 最大 2 MB，EPUB 最大 8 MB，PDF 最大 10 MB。仅显示纯文字预览，不将原始文件上传到 Storage、不自动缓存、不会尝试在线 PDF OCR/远端转换，没有使用付费服务。打开文件只做本地处理，与用户的上传同意分离。

## 自动验收

- \`lib/v2/txt.ts\`、\`lib/v2/epub.ts\`、\`lib/v2/pdf.ts\` 负责纯文字导入；UI 使用 \`app/v2/V2TxtImporter.tsx\`。
- Node 单元测试 \`tests/unit/txt.test.mjs\`、\`epub.test.mjs\`、\`pdf.test.mjs\` 检查章节映射、中文/emoji 分段、非法文本、EPUB CRC/路径穿越/重复 ZIP 文件名、尺寸上限及 PDF 字符和页面配额。
- \`tests/browser/pdf.html\` 和 \`tests/browser/run-pdf.cjs\` 在真正的无头 Chromium 中从当前站点载入 PDF.js 与其 worker，解析内存中构造的有效 PDF，检验文字层提取与空白页拒绝；无跨站请求。工作流仍回归真实 Chromium 适配层、响应阅读与单行文字重排。
- PostgreSQL 安全测试入口 \`tests/sql/reading_import_v2_smoke.sql\` 串联前序所有双人 RLS 和审计测试，专门验证重复段落无配额消耗、不同原文不能覆盖、非法/越权房间拒绝、章节写入幂等和房间关闭撤权。
- GitHub Actions 最后必须全部通过：Node 单测、严格 ESLint、Next.js 静态构建、浏览器 PDF.js、隔离 PostgreSQL 16 安全回归。

## 不应夸大的限制

- **PDF 扫描件、电子书 DRM、版权受限内容、复杂固定版式、插图、表格与真正 OCR 仍不支持。** PDF.js 只导出可提取的文字，列布局、文内图片及复杂字体可能产生错误阅读顺序；应先让用户检查本地预览。需保留原书真实视觉版式的多媒体阅读引擎不属于此版纯文字导入。
- PDF 解析已在真正 Chromium 的独立测试夹具中验收，但**没有**跑真实 iPhone Safari、Android Chrome、屏幕阅读器或实际双人 Supabase 的整页上传 E2E；由第 14 模块完成。
- 单次每日上限 300 段与固定书房上限 2000 段不是对无限本图书的保障。超配额须停止或选择更短、具有上传权的内容，绝不绕过安全限制。
- 这个模块不执行生产迁移，不合并草稿 PR，不修改 \`main\`、旧书数据或生产 Supabase。

**本模块代码/自动测试 100% 仅限上述可验证的纯文字格式导入范围。**
