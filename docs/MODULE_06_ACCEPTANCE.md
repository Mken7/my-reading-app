# 一级模块 06 · 重叠划线、私人/共享批注与讨论回复

**状态：开发分支代码和自动化测试验收（以最终 GitHub CI 成功为准）；未部署至正式 Supabase。**

本文件按用户约定对第 06 个**完整一级模块**统一验收，而非对子功能分别宣告交付。

## 已实现功能

1. **完整选字与重叠划线**：鼠标/触屏选中文字，也可用键盘填写首尾字符序号。段落锚点使用 Unicode 码点，中文、emoji、多个 React span 均可按原文字范围定位。两个人可以在同一区间做不同批注，蓝色代表本人、玫红代表伙伴、重叠为紫色；任何人的文字批注都不会覆盖对方的原始记录。
2. **私人与双方共享**：新批注明确选择“仅自己”或“双方共享”，默认私人；独立的数据库 RLS/可信 RPC 限制仅活动房间成员访问共享内容。伙伴、陌生人、退出/已关闭书房均不能查看未授权内容。
3. **批注编辑**：仅原作者可修改自己批注的文字和可见范围，不能改变书房/段落/选字区间/作者。修订号采用 compare-and-swap，旧设备不能覆盖新设备的编辑，冲突时编辑框保留文本以便人工核对。如果已有回复则锁定私人/共享范围，避免把私人回复意外公开或让对方已有回复突然变为私人。
4. **批注撤销**：原作者可二次确认撤销整条批注，包括其下的回复可见性。数据库使用受保护的 `v2_hide_highlight` 写入软撤销时间、作者，自动增加修订号、追加带摘要的链式审计事件。撤销之后不能通过旧发送 UUID 恢复，伙伴/本人都不能再普通读取该批注及其回复。
5. **两人讨论回复**：共享批注可供两人回复、私人批注只允许作者追加。每处批注最多 100 条、单条正文最多 2000 个字符；回复只在讨论展开时加载。回复由用户手动发送，编辑框能保留 AES-GCM 加密离线草稿，服务器按客户端操作 UUID 幂等判断网络重试，避免重复发送。原作者可二次确认撤销自己的回复，别人不可撤销。
6. **配额与浏览器性能**：每位读者每一段最多保存 60 条文字批注，每次新建采用事务级顾问锁限制并发冲破配额；已经软撤销的批注仍计入总量。前端每个段落查询上限 150 条笔记，单处讨论查询上限 100 条回复，避免无界查询。
7. **审计链与安全权限**：批注创建、带修订号的修改和软撤销、回复创建及撤销都写入房间 SHA-256 链式事件摘要。审计表不存批注正文，只存哈希及操作元信息；该链尚没有外部签名与锚定，不能宣称绝对不可篡改。普通客户端只有经 RLS 授权的读取和新建权限，无法直接 SQL UPDATE 旧批注，必须使用验证作者与修订号的 RPC。
8. **现有模块集成**：第 07 模块的图形笔迹可以和文字批注重叠；第 08 模块可记住 Unicode 精确阅读位置；第 09 模块手动加密待发送队列保留原操作 UUID。不会擅自自动发送私人草稿，也不将书房中他人内容变成公共数据。
