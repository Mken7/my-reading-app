# V2 多条加密待发送草稿队列（仅隔离测试版）

**尚未上线。** 只在 `feat/phase0-foundation-2026-10-18` 的 V2 阅读器代码中实现；不涉及线上 Supabase，不允许擅自合并 `main`。

**当前推荐：IndexedDB 原子加密队列。** 下文 `localStorage` 相关内容仅说明仍可恢复的旧版队列和单份加密备份；新版的代码与验收边界见 `docs/V2_INDEXEDDB_MODULE.md`。

## 已实现

- 同一账号 + 书房 + 段落/笔记位置下，最多保留 **10 条**独立的待发送文字批注或回复草稿。列表显示数量和匿名序号，正文、可见性、选字位置均不以明文写入浏览器缓存。
- 新版：只有用户主动点击「加密加入可靠队列（IndexedDB）」才写入 IndexedDB。每条操作绑定一个随机 UUID，沿用 Web Crypto AES-GCM、随机盐/IV 与 PBKDF2 派生密钥；解锁口令不存本机数据库也不上传。旧版 `localStorage` 备份入口保留供用户自行恢复与清除。
- 密文采用账号、书房、记录类型、目标位置及发送 UUID 作关联认证数据（AAD）；索引只存随机 UUID，不含读者姓名、笔记明文或 `private/shared` 状态。相同 UUID 不允许以不同正文或共享范围覆盖旧草稿。
- 用户逐条输入口令进行恢复，然后必须在正常编辑框检查隐私范围和文本，再主动点发送。数据库 `v2_submit_highlight` / `v2_submit_reply` 以相同 UUID 实现幂等重试，避免网络 ACK 丢失导致同一操作重复创建。
- 在线发送得到 `saved` 或 `already_saved` 后，只删除该 UUID 对应的本地加密待发送项；其余未发送记录保持原样。每条支持二次确认后清除。
- 以前只有一份草稿的旧版加密备份仍可手动恢复、覆盖、清除，**不会因为发送了其他队列项目而误删**。这两个存储机制暂时并存。

## 重要限制

- 这是**手动待发送列表**，不是后台自动重试任务，不会在重新联网后发送私人内容。每条必须恢复到编辑框并由用户主动确认发送。
- 不会自动跨设备共享；用户可点击“导出加密备份文件”，在同一登录账号、书房及目标笔记位置用口令验证后**手动导入**。导入通过完整的 AES-GCM 认证并在一笔 IndexedDB 事务中合并，重复操作 UUID 或超配额均拒绝整个导入。无痕模式、清理网站数据、忘记口令、磁盘故障仍可能使密文永久丢失。
- 最大数量为每个*具体目标位置* 10 条，而非整个账号共 10 条；尚无全站总容量配额与长期淘汰策略。浏览器存储配额满时会报错。
- 索引中保留随机 UUID 及其数量，并非完全隐藏元数据。恶意同源脚本、恶意浏览器扩展、弱口令、操作系统入侵依旧属于风险。
- 已为同源多个标签页的**待发送队列新增和移除**接入浏览器 **Web Locks API**：加密、容量判断、目录读写处在相同位置的独占锁内，避免两个标签页同时更新索引造成最后写入覆盖。其他标签页操作后，通过 `storage` 事件刷新列表。
- 不支持 Web Locks 的浏览器会**阻止队列新增及清除**，但仍可查看并尝试解密恢复已有草稿；不会降级为不安全的并发写入。旧页面版本若仍在浏览器中运行、恶意同源脚本绕过锁，以及浏览器崩溃/磁盘中断不在此保证内。
- 新版 IndexedDB 队列每条草稿是一条对象存储记录，重复编号检查、容量限制和写入都在同一读写事务中进行；旧版 `localStorage` 队列仍需要 Web Locks。多标签页各自打开的草稿输入框不会自动合并，正式发布前还需要 Safari/Chrome/Firefox 实机 E2E、崩溃恢复和断电测试。
- 如果编辑器中还保有另一条不同的草稿，恢复会拒绝覆盖，以避免静默丢稿。当前只有按每条编号恢复，不提供全房间集中搜索列表。
- GitHub CI 现在额外在真正的无头 Chromium 中运行 IndexedDB 加密队列写入、恢复、重试冲突拒绝及加密文件导入/导出的集成测试。仍需独立 staging Supabase 的双账户验收和 iOS/Android Safari/Chrome 真机测试。

## 本模块验收清单

- [x] 单一写操作独占哈希化的队列目录锁，不包含用户名/正文等明文。
- [x] 同时加入不同 UUID 不丢失已保存项，同时删除与新增保持剩余项。
- [x] 不支持安全锁时拒绝修改，而非静默按旧逻辑覆盖。
- [x] 其他标签页更改索引后刷新当前阅读器的数量。
- [ ] 实机浏览器多标签页、版本不一致的旧网页、磁盘崩溃与 IndexedDB 原子事务验证。

## 新版持久化与健康检测

- UI 支持用户主动测试 IndexedDB 写入与清理、查询浏览器存储占用估算和是否授予持久存储权限；浏览器支持时可在按钮点击后尝试申请减少自动清理。
- 即使显示持久存储已授予，也**不能保证**清理网站数据、卸载、硬件故障或私密窗口结束后仍保留草稿。
- 已添加 Node 单元测试和 CI 代码检查；真实移动设备、浏览器崩溃的行为仍需专门测试。参见 `docs/V2_INDEXEDDB_MODULE.md`。
