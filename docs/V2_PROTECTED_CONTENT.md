# V2 私有正文访问模块（测试实现，未上线）

## 实际接口和界面

迁移 `supabase/migrations/20261018231000_v2_private_book_chunks.sql` 提供：

- `public.reading_chunks_v2`：按书房和从零开始的段落序号保存正文，单段 1–3000 字，最多 2000 段（不保证可以覆盖所有超大书）。
- `public.v2_upload_book_chunk(room,index,text)`：只有活动书房房主能增加**不可覆盖**的新段落，每位账号 24 小时上限 300 段。上传不支持修改和删除，后续正式版本必须增加合规修订、删除与版本管理。
- `public.v2_read_book_chunks(room,index,count)`：每次最多读取 2 段，服务端再次检查 JWT 身份、成员资格、书房状态，并在数据库事务中累计每成员每书房 1 小时最多 60 段的限额；无成员资格或超限时返回空结果。短暂网络错误可能需要重试。
- 原始正文表及读写配额表不给 `anon` 和 `authenticated` 角色任何直接读取或修改权限。读取与上传均经 `SECURITY DEFINER` RPC，客户端不得携带 `service_role` 密钥。
- 不依赖 `robots.txt`、前端禁用复制、JS 混淆或浏览器 IP 作为权限依据。

`app/v2/V2ProtectedBook.tsx` 提供简化的*测试面板*：房主手动上传合法的短文本，成员按段阅读。

### TXT / EPUB / PDF 本地导入

- `lib/v2/txt.ts`：纯本地、无请求的 TXT 解码与确定性切分，支持 UTF-8 与 GB18030/GBK；统一 CR/CRLF 换行，保留空行及文本内容，按 Unicode 码点拆分，避免拆断中文扩展字符和 emoji。自动检测部分“第 X 章 / Chapter N”标题，完整上传后会通过受保护的数据库接口登记目录，供双方查询跳转。
- `app/v2/V2TxtImporter.tsx`：房主选择本地 `.txt`、`.epub` 或 `.pdf`，先预览统计、章节标题与段落，**只有主动勾选上传权声明并点击上传**才开始向独立测试书房逐段写入。关闭/刷新页面后不会把 TXT 自动恢复到本地存储；该功能不上传用户未选择的文件。
- TXT 文件上限 2 MB、EPUB 上限 8 MB、PDF 上限 10 MB，每段目标 2800 码点、单次导入最多 300 段（对齐服务器当前 300 段/账号/24 小时额度）。服务器总共支持 2000 个序号；本地预览不计后端流量额度。
- 上传按顺序提交；服务器拒绝（不同原文、限额、权限、网络等）立即停止，不跳过、不覆盖。断线导致无法确认时，重新上传相同索引及文字会收到 `already_saved`，不重复扣额度；旧段落内容不同则返回 `conflict`。该受信 RPC 仅向当前房主开放，不透露其他账号的正文。
- EPUB 预览通过 `lib/v2/epub.ts` 在浏览器本地解析 ZIP 中央目录，校验 CRC、压缩算法、路径与大小限制，按 OPF spine 顺序提取 XHTML 的**纯文本**。书中 HTML 不会作为页面 HTML 渲染，也不会发起书内资源请求；DTDs、加密/DRM 内容、恶意路径与可疑 ZIP 膨胀包被拒绝。
- EPUB 文件上限 8 MB，最多支持 150 个有序章节、1,000,000 个文本码点；图像、表格精确排版、CSS、媒体与字体不保留。仅提供纯文本章节预览，不承诺完整再现原书版式。部分老旧 EPUB 的非 UTF-8 XML、部分特殊 ZIP 结构可能不受支持。
- PDF 支持本机 PDF.js 纯文字层解析，最多 120 页、100 万字符；不提供扫描 OCR、加密 PDF 绕过、完整视觉排版或插图。**仍不支持**书籍版本替换和正文自动离线同步。章节目录及每个账号的书签已在 V2 测试数据库实现。较长的 TXT/EPUB 可能无法在单日上传额度内导入；正式版需设计更合理的存储、配额及合法导出。当前代码尚未在真实 Supabase 测试环境及浏览器端到端验证。

## 权限与容量限制

- 必须使用独立的 V2 Supabase 测试项目并明确设置 `NEXT_PUBLIC_ENABLE_V2_PREVIEW=true`。未经配置时，V2 预览关闭；代码不会替换或迁移旧表。
- 每书房理论最多 2000 × 3000 字；单账号每日上传上限意味着一部完整书籍可能需要多日上传。这些数字只适用于安全原型，正式版应基于用户测试、版权要求、存储成本和无障碍需求重新制定。
- 每成员每书房每小时最多 60 段、每次最多 2 段。每人分开计数，不能用于阻止受授权读者截图或提取已经显示的文字。
- 当前未配独立网关、IP/设备限流、自动化行为分析或后端全文版权审核；仍可能受到大量账号、低速持续抓取等攻击。
- 现有书籍正文没有迁移；`public.books`、旧版笔记表和真实数据均未改动。

## 自动化验证

`tests/sql/reading_import_v2_smoke.sql` 继承先前的成员、邀请码、审计链与配额回归测试，新增：

1. 只有房主能上传，重复段落序号不能被覆盖，超大内容/非法序号被拒绝。
2. 成员可读取允许的段落，但不得直接查询整张正文表。
3. 非成员即使拿到房间 UUID 也无法阅读或上传；匿名角色不能执行读取 RPC。
4. 持续读取会触发 60 段/小时限制，上传会触发 300 段/24 小时限制。
5. 书房关闭后，即使曾是合法成员也无法再次取到正文。

这些测试只在 CI 的隔离 PostgreSQL 16 容器中执行；不能替代真实 Supabase Auth、存储、Realtime、压力测试和端到端渗透测试。

新增 `tests/unit/txt.test.mjs`、`tests/unit/epub.test.mjs`、`tests/unit/pdf.test.mjs` 和 `tests/unit/overlap.test.mjs`，使用 Node 22 内置测试运行器：覆盖中文/emoji 断字、换行、章节识别、文本编码、合成 ZIP 的 STORE/DEFLATE 解压、CRC 校验、目录穿越、重复 ZIP 路径、加密标识和可疑 ZIP 膨胀。PDF.js 已在无头 Chromium 中通过真实文字层提取测试；真正的 Chromium 已覆盖 EPUB ZIP/DEFLATE、XML/XHTML 文本抽取及脚本隔离，但 React 上传整页、手机真机和实际双人 Supabase 端到端验收仍未完成。PR 必须同时通过单元测试、严格 ESLint、Next.js TypeScript 构建与数据库安全测试。

## 不能马上上线的原因

需要在隔离 Supabase 测试项目验证完整邮箱登录流程、实际 JWT 和 RLS、合法上传/更新/删除、内容导出、离房/封禁、完整书籍分段阅读的性能；引入 Edge Function 或受保护的网关控制 IP/设备风险、限流误判申诉，核实免费额度，再处理旧数据迁移及回滚。**未经这些验证，不合并 PR #1，不修改 `main`。**
