# V2 邮箱登录 / 双人书房预览（仅测试环境）

**状态：未上线，不可用于真实书籍或真实账号。**

## 已实现的界面

- `/v2/` 是与旧版首页完全分开的 Next.js 静态路由。
- 用 Supabase Auth 完成邮箱+密码注册和登录、恢复测试会话、退出登录。
- 登录后通过 RLS 查询自己的 V2 书房，并允许在**测试数据库**创建书房。
- 房主在测试数据库生成、轮换六位邀请码；新伙伴提交请求后必须等待房主审批。
- 房主查看待审核申请并允许/拒绝；服务端 RPC 负责权限判断。
- 不渲染旧版书籍全文或读取旧版匿名 localStorage 身份。

## 强制隔离与启用方式

没有以下全部配置时，`/v2/` 只显示“预览默认关闭”的静态说明，不会请求任何测试登录或数据库数据：

```dotenv
NEXT_PUBLIC_ENABLE_V2_PREVIEW=true
NEXT_PUBLIC_V2_SUPABASE_URL=https://YOUR-SEPARATE-STAGING-PROJECT.supabase.co
NEXT_PUBLIC_V2_SUPABASE_PUBLISHABLE_KEY=YOUR_STAGING_PUBLISHABLE_KEY
```

- 仅为**单独创建的测试 Supabase 项目**填写以上变量；绝不填入已有的线上项目。
- 程序显式拒绝旧版项目 URL（`warhfmpfnlgzofbeuikb`），也不回退到 `lib/supabase.ts`。
- 变量保存于本地未提交的 `.env.local`；不要提交任何 `service_role` 或管理员密钥。
- 在隔离测试库按照文件名顺序应用 `supabase/migrations/20261018*.sql`。不要在原有数据库执行。
- 用测试邮箱配置该测试项目的 Supabase Auth。若开启邮箱确认，注册后需完成邮件验证。
- 本地运行 `npm run dev`，打开 `/v2/`。实际前端验证必须在配置完整的测试项目中开展。
- CI 只验证构建、ESLint 以及模拟 PostgreSQL 权限；**尚未跑真实 Supabase Auth 端到端测试**。

## 服务端配额（测试代码已实现）

- 每账号单个 24 小时滑动窗口最多 **3 次成功创建书房**。
- 每账号单个 24 小时滑动窗口最多 **10 次成功签发邀请码**。
- 每账号一小时 **5 次邀请码提交尝试**。
- 房间最多两个座位；主人审批后邀请码单次使用，轮换、过期和无效邀请码不可加入。

以上配额由数据库事务中的触发器/RPC 实施，非前端计数。**仍不能抵御批量注册、跨账号猜码、IP 级抓取**；用户端的 `NEXT_PUBLIC_*` 值不具备保密性。

## 正式启用前的阻断项

1. 使用三组实际 Supabase 测试账号，验证注册确认、登录、登出、邀请码、撤回审批和 Realtime RLS。
2. 配置可信代理/Edge Function 的 IP、网络和设备风险限制（注意隐私和无障碍），并实现请求监控、可操作的申诉流程。
3. 保护书籍正文：授权后按章/页配额交付；静态托管不能防止有权限者复制已显示的文字。
4. 实现账号删除、退出双人阅读、封禁、冻结共享数据与合规导出。
5. 经过数据迁移、回滚演练和真实 Supabase RLS 审计，才可考虑从旧版转向 V2。

目前 `main` 没有改动，线上数据库也未执行迁移。以上步骤均不是用户现在必须完成的操作。
