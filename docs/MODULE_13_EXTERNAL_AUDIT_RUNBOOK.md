# 模块 13：独立审计签名与版权/举报操作手册（未实际上线）

此说明只适用于单独的 V2 staging 测试库。当前没有正式外部审计合同、真实签名锚点或安全审查批准。任何人不得将“有离线签名工具”宣传为“已通过独立审计”。

## 书籍权利声明

房主在上传前使用 `v2_confirm_book_rights(room_id,rights_basis)`，其中依据是 `original`（原创）、`public_domain`（公有领域）或 `licensed`（已有授权）；数据库阻止没有声明的新正文写入。客户端不可直接修改声明历史。平台仍须建立版权投诉受理、通知与申诉流程，并核验地域、期限及授权范围。未知版权的书籍不要上传。

## 审核人任命与投诉

运营者只在经授权的 staging SQL 管理会话中为确需处理案件的真实测试账号填入 `reading_v2_trusted_reviewers`。应用不提供自我提权功能，任何普通用户也不能读取原始举报表。案件需要先标记 `reviewed` 并记理由，之后才能 `closed`；举报人能查看自己的状态。移除审核人访问时，运营者须直接在可信管理会话撤销其表内身份，并审查当前登录令牌及访问日志。不得将服务端管理密钥放进浏览器。

## 离线第三方验证流程（尚未执行）

1. 在信任范围内，使用已授予审核权限的会话调用 `v2_export_audit_evidence`，设置 `target_room`、`after_seq=0`、`page_size=100`，并每次把 `after_seq` 设为上一页的最后一个 `sequence_number`，直至返回空页。拼接为包含 `room_id` 和 `events` 数组的 JSON。事件对象应保留 `sequence_number`、`previous_hash`、`event_hash` 及 `canonical_event` **原始字符串**；不得重新序列化 canonical_event，也不能省略中间页。
2. 一位被独立确认身份的审计人在线下安全主机上，使用自行保管的 Ed25519 私钥运行 `node scripts/sign-v2-audit.mjs evidence.json private-key.pem receipt.json`。工具先核对连续哈希链，发现任何缺页、改写或乱序都会拒签。
3. 将 `receipt.json`、审计人身份说明、固定的公钥和签署时间存储于**与应用数据库分离、不可由同一管理员任意重写**的媒介，记录保留期限。私钥永不进入代码仓库、在线页面或日志。
4. 任意复核人离线运行 `node scripts/verify-v2-audit.mjs evidence.json receipt.json pinned-public-key.pem`。命令仅在整条提供的链与已签收据完全匹配时返回成功。**必须另外核对已签收据中的事件数与可信数据库最新链头**，否则一条自洽但被截断的旧链并不能证明完整历史。
5. 轮换审核公钥时，保留历史签名对应的旧公钥及可信指纹，不可使用从待核验数据库临时取出的“公钥”。签名只约束已锚定的版本，对尚未锚定的事件和管理员同时掌握数据库及密钥的情况没有证明力。

## 发布门禁

- 需在非生产 Supabase 项目执行真实多账号权限、并发、恢复、断网测试并审查 RLS、Realtime、数据擦除。
- 在任何开放公共书房目录之前，必须落实 IP/网络、设备与跨账号滥用防护、可追溯举报处理、申诉及版权撤回流程。
- 需真实第三方独立安全审计与外部签名锚定演练；目前仅交付验证接口，不声称实际完成。
- 运营/法律复核需要针对适用司法辖区明确隐私、侵权处理和审计证据保留期限，不能用哈希或用户勾选替代合法性审查。
