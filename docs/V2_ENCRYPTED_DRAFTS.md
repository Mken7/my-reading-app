# V2 本地加密草稿（仅测试实现）

本功能仅在独立的 V2 staging 预览中使用，**不涉及生产 Supabase 或旧版书籍数据**。

## 功能边界

- 文字选区批注与回复都支持「本机加密草稿」。用户必须主动输入独立口令（12–128 字符）并点击「加密保存」，**不会自动把输入明文写入 localStorage**。
- 加密记录位于本浏览器当前网站来源的 localStorage。通过浏览器原生 Web Crypto：AES-256-GCM、每次新的 16 字节随机盐、12 字节随机 IV、310,000 次 PBKDF2-HMAC-SHA256。
- 加密使用 userId、roomId、draft kind（highlight/reply）、目标段落或笔记 ID 的有序上下文作为 AES-GCM 认证关联数据（AAD）。存储键是该上下文的 SHA-256 摘要，而不是直接把文本或账号 ID 写入键名。复制密文到另一账号/书房/目标位置无法正常解密。
- 每个草稿明文最多 8 KiB，密文信封最多 16,000 字符。文字选区草稿包含正文、起止 Unicode 字符位置和私人/共享状态；恢复时检查选区仍落在当前不可变正文内。回复草稿只包含未发送的回复正文。
- **解锁口令不发送到数据库，也不由本应用保存。** 每次手动操作完毕后清空组件的口令输入状态。忘记口令则无法恢复。
- 成功发送到服务器后，尝试从 localStorage 删除对应加密备份；若浏览器禁止存储操作，会提示需要自行清理。恢复草稿不会自动发送，必须再次点击正常的在线保存/回复按钮。

## 注意事项与威胁模型

- 本地加密可以降低别人在同一个浏览器直接查看 localStorage 时读到草稿明文的风险，但不能抵御已经运行在网站页面里的恶意脚本、恶意浏览器扩展、被入侵的操作系统，或用户输入弱口令造成的字典攻击。
- 不同浏览器或设备**不会自动同步密文**；网站数据被清空、无痕窗口关闭或浏览器清理缓存都可能永久丢失草稿。保存长文稿请另行保留安全备份。
- 此功能不是持续自动保存或可靠的离线队列。断网时若事先没有点击加密保存，当前未发出的文字只留在页面内存中；关闭页面可能丢失。
- 本地密文不会被服务器直接管理或远程清除。撤销账号授权、删除云端笔记、退出登录，均不自动销毁另一台设备上的离线密文；需另行制定数据保留和删除政策。
- 当前没有多标签页冲突协调、笔记草稿版本历史、自动到期清理，也没有高保真手机端端到端验收。真实离线同步与多设备合并需要单独设计。

## 测试

`tests/unit/encryptedDraft.test.mjs` 覆盖中文/emoji 往返恢复、明文不入存储键与密文记录、随机盐/IV、错误口令、修改密文、跨账号/书房/草稿目标隔离（含复制密文攻击）、清除与格式校验。GitHub CI 还运行严格 ESLint、Next.js 静态构建及 PostgreSQL 安全回归测试。

V2 代码仍保留在草稿 PR #1，`main`、生产 Supabase、正式读者数据和付费资源均不改动。
