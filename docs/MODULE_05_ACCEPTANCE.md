# 一级模块 05 · 沉浸式阅读器、响应式单双页与磨砂玻璃工具

**验收口径：开发分支的既定功能与自动测试（需以最新 CI 全通过为准）。未部署、不是正式用户验收。**

本次只完成第 05 个一级大模块，沿用已验收的第 06～09 模块数据模型，不新增生产数据库迁移。

## 完整模块交付

1. **实际的单双页阅读**：浏览器视口不足 1100px 时只按需读取并显示一段原始正文；达到 1100px 时最多读取两个相邻、连续、经过验证的不可变段落，每段单独构成一页。右页不是复制左页或伪造两栏，二者有各自的段落编号、独立文字划线、图形、私人/共享批注、回复和精确位置。
2. **响应布局**：单页窄屏、双页宽屏，页纸采用克制的边框、内边距和书脊分隔。浏览器缩小时不会让右侧批注错误地并入左侧；重新变宽时只按需补取右页，且这次补取**不会**增加或覆盖私人云端阅读进度的服务器版本号。页面没有必要的横向溢出，阅读末尾留出移动端浮球及安全区。
3. **翻页与跳转**：上一组/下一组按钮按当前布局移动一页或两页，可直接输入 0～1999 的段落号并前往。页纸可通过 Tab 聚焦，聚焦后左右方向键翻页；在输入框、批注编辑器、菜单和文字选择期间不夺取方向键。键盘翻页后焦点留在新页面。不可访问/未上传右页显示明确的空页提示，不虚构正文。
4. **网络与权限保护**：实际正文只通过受权限控制的 \`v2_read_book_chunks\` 获取，返回记录必须具有正确、连续的段落编号，最多读取一段或两段。读不到下一页、权限错误、请求抛错都不会清空已经打开的正文或正在写的批注；不得将缺失的右页用前一段重复填充。服务器仍有独立的每成员/书房读取配额。
5. **跨模块交互保持独立**：第一页、第二页各持有正确的 Unicode 字符偏移和作者批注；在右页保存字符级阅读位置、创建私人段落书签时提交**右页自己的段落编号**。这不会读取共读伙伴的私人书签，也不会绕过 06～09 模块的可见性与 CAS 防冲突限制。
6. **专注阅读**：房主导入/上传控件和书签/目录管理默认折叠，用户有需要时展开，不挡住正文。悬浮磨砂玻璃工具提供目录、书签、批注显隐、房间成员、阅读设置；工具执行后焦点返回浮球。共读面板只显示已加入成员，不伪称实时在线。
7. **字体与主题**：可即时更改字号 14～24px、行距 1.5～2.3、暖纸／白纸／雾灰色。笔迹原有的单行重排保护继续生效；这些仅是当前页面设置，不会擅自存入服务器或跨设备同步。
8. **无障碍与动效**：页纸/按钮具有焦点轮廓、中文说明，悬浮菜单支持 Tab/Enter/Escape，尊重系统减少动画/减少透明度和高对比度，控件避免被移动端底部安全区覆盖。未安装新的 UI 库、外部素材或付费服务。

## 自动验收范围

- 响应逻辑：\`lib/v2/readerLayout.ts\` 与 \`tests/unit/readerLayout.test.mjs\`，验证 Unicode 文本、最小/最大段落号、翻页步长、服务器返回乱序或缺段过滤。
- 界面和样式：\`app/v2/V2ProtectedBook.tsx\`、\`app/v2/V2GlassDock.tsx\`、\`app/v2/reader-pages.css\`、\`app/globals.css\`。
- Chromium：\`tests/browser/reader.html\` 和 \`tests/browser/run-reader.cjs\` 在窄/宽无头 Chromium 视口加载实际响应 CSS，核对单页/双页数目、没有横向溢出、可聚焦阅读纸张及翻页纯逻辑。保留原加密、DOM Range 与双人隐私回归。
- GitHub Actions 必须通过：Node 单元测试、严格 ESLint、Next.js/TypeScript 静态导出、实际 Chromium 响应布局/加密/文字重排、隔离 PostgreSQL 16 RLS/审计回归。

## 明确未声称完成的项目

- 真正的 iOS Safari／Android Chrome 真机、手机读屏器／触控／虚拟键盘、正式独立 staging Supabase **双账号端到端**由第 14 大模块集中验收；Chromium 宽窄视口检查不是手机真机测试。
- 由于按数据库的不可变段落为分页单位，某段若过长会让页面高度自然增长；这不是自动按屏幕高度拆分为相等纸页的排版引擎。专业 EPUB 版式还原及 PDF 文件导入属于第 04 模块。
- 这里没有双方实时同步翻页、实时在场判断、对方位置共享或完全防剧透同步；这些属于第 10 模块。也不宣称已有可在所有浏览器上运行的全屏/沉浸模式 API。
- 偏好当前仅驻留内存；刷新页面或换设备不保证字号、背景完全一致。用户上传出版物需要合法授权，正式版权与审计/数据删除属于第 12～13 模块。
- 代码只存在于 \`feat/phase0-foundation-2026-10-18\`，草稿 PR #1。不得直接合并 main、修改生产 Supabase、部署上线或启用收费服务。
