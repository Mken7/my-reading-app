# 一级模块 11 · 书房发现、举报与屏蔽 · 代码验收

**状态：仅开发分支的代码功能及自动测试验收完成。不是生产上线验收，不能向公众开放陌生人广场。**

## 交付范围

1. **默认私密与主动发现。** 旧书房和新书房均默认不列入目录。活动书房仅在房主明确设置独立的公开招募标题（1–80 字）及可选简介（≤240 字）后被搜索；原有私密书籍标题、正文、批注、成员邮箱、邀请码、个人阅读进度和身份标识不进入公开卡片。最多返回 20 个结果；满员、归档或已关闭的书房自动被筛除；房主可随时撤下，撤下同时使未处理公开申请失效。
2. **受控的发现申请及二人席位。** 通过公开目录直接提交加入申请，不需要获取/破解私密邀请码；申请人可查看自己的状态并撤回；房主仅查看自己收到的待审申请编号并明确同意或拒绝。批准通过同一个房间行锁、成员唯一约束、在途申请批量拒绝来保证最多两位成员，同时撤销旧邀请码并撤下公开卡片；申请永不自动入房。
3. **双方主动屏蔽。** 可屏蔽公开卡片的房主；房主可屏蔽与其书房确有申请关系的账号；本人可以在只对自己可见的屏蔽名单解除屏蔽。双向屏蔽过滤搜索与发现申请，并用数据库触发器同时禁止通过旧邀请码或审批 RPC 绕过屏蔽、创建新伙伴席位；不冒用浏览器上的用户 ID。对已有成员暂不偷偷踢出或销毁私人笔记，退出/剔除与历史数据处理留给模块 12。
4. **私密举报处理。** 可以就用户已可看到或已有联系的招募卡片提交骚扰、垃圾信息、版权、隐私及其他问题（说明 10–500 字）。举报正文与举报人身份仅保存在未向普通客户端开放的服务端表；给用户确认已提交，不自动定罪、公开举报或向被举报者泄露。
5. **滥用节流与明确失败。** 每个账号 24 小时至多五次目录加入请求、五次举报；不存在或不可访问的房间统一返回“不可用”，不公开未经列出的房间、申诉细节或其他账号的申请记录。数据库持久化尝试计数，不能通过删除前端缓存刷新限额。
6. **安全隔离。** 全部新数据库表启用 RLS 并撤销匿名/普通客户端的直接访问，通过固定 search_path 的受保护 RPC 在服务端查询；房主审批与屏蔽用同一房间行锁避免并发误批。页面使用与旧版分开的 V2 独立登录会话，账号切换后取消旧查询；不改变旧版数据与线上账号。

## 重要上线阻断项（未完成，不计入本模块的真实验收）

- **没有部署至真实测试 Supabase**：需三组以上真实 Auth 账号验证数据库迁移、并发审批、行级权限、交叉屏蔽及 iOS Safari/Android Chrome 浏览器交互。不能以单机 PostgreSQL 或模拟身份代表这些真实 E2E。
- **公众广场仍关闭**：正式开放陌生人发现之前必须实现服务端 IP/设备/跨账号速率限制、人工审核和举报处理时效、申诉机制、滥用处理日志、内容/隐私政策、版权合规、安全审查。当前仅提供私密队列的结构和入口，尚未建立真正的值班审核/申诉运营体系（模块 13）。
- **设计选择**：不将真实书籍/笔记作为公开发现内容；两个账号之间的屏蔽仅防止新关联，不追溯清除或强制踢出已有成员；这不是完整数据销毁承诺（模块 12）。
- **发布规则不变**：保留 main、2026-10-18 备份分支与旧 Supabase；仅在 draft PR #1 的 `feat/phase0-foundation-2026-10-18` 增加代码。不合并、不执行生产迁移、不增加付费服务。

**工程验收口径**：模块 11 的前后端代码与隔离自动检查完成，可以记录 100%（代码验收）；正式上线准备度不因此提高或对真实陌生用户开放。
