# 一级模块 09 · 本地加密、离线草稿与待发送队列 · 验收结论

**状态：代码功能验收完成；整体产品仍未上线。**
本文件按用户约定仅对第 09 一级模块整体出具一次验收，不把小组件作为一次独立交付。

## 已实现并经过自动验证的模块功能

1. **私人草稿保护。** 用户主动设置独立的 12–128 字符口令，使用 PBKDF2-HMAC-SHA256 派生 AES-256-GCM 密钥；加密记录携带随机盐和 IV，绑定账号、书房、笔记目标及发送编号的认证关联数据。口令和笔记正文不以明文写入持久存储。
2. **离线暂存、恢复与保留。** TXT/EPUB 阅读器的文字选区笔记及批注回复都能离线加密保存，之后手动输入口令恢复。没有口令就不能在该网站中恢复明文，也不会自动将未审阅的私人草稿发送出去。
3. **10 条独立待发送项目。** 每个具体书房/笔记目标下最多 10 条加密待发送项，按 UUID 恢复、清理，使用 IndexedDB 单条对象记录和原子配额检查；多标签页同时写入不覆盖其他记录。
4. **网络重试安全。** 服务端通过账号/书房/操作 UUID 唯一约束防止相同请求重复创建批注、回复或审计事件；更改正文、文字位置或 private/shared 范围会返回冲突；撤销过的回复不因重试复活。
5. **成功发送后的精确清理。** 仅移除已获服务器确认的操作 UUID 对应的加密本机项目，不抹掉其他未发送草稿，也不自动删除旧版备份。
6. **存储诊断和兼容恢复。** 使用用户触发的 IndexedDB 探测与浏览器存储持久性查询，支持申请降低自动清理风险；保留旧版 localStorage 加密草稿和 Web Locks 队列的解密/清理入口。
7. **跨设备手动转移。** 用户可下载不含正文明文的加密备份 JSON，拿到另一设备，在同一账号、书房和目标位置手动选择文件、输入原密码验证，再使用单个 IndexedDB 事务进行整批导入；不会云端偷偷同步或发送。
8. **完整测试门禁。** Node 单元测试包含加密、账户隔离、上限、私密范围、并发读写、冲突和损坏文件处理；GitHub CI 使用真正的无头 Chromium 验证原生 IndexedDB 写入、恢复、删除及手动加密文件导入/导出；PostgreSQL 16 隔离数据库检测双人 RLS、幂等重试与审计链，另外运行严格 ESLint、TypeScript 和 Next.js 静态构建。

## 边界及不属于本模块的项目

- **不会后台自动发送。** 即使互联网恢复也必须用户解锁、核对可见性并点击发送；这是避免私人草稿在未经再次确认时公开的设计约束。
- **不是云端同步服务。** 当前仅有加密文件手动转移；书签/阅读进度的跨设备云端同步属于第 08 一级模块，真正的全房间实时同步属于第 10 模块。
- **还不是上线验收。** iOS Safari、Android Chrome、整个 React 页面和实际 Supabase 双账户的端到端测试，以及崩溃恢复/真实设备存储回收验证，统一由第 14 模块处理；正式上线前必须通过，不能拿 Chromium 单测代替。
- **清除网站数据、无痕模式、设备损坏、忘记密码仍会造成草稿不可恢复。** IndexedDB 原子事务不会提供硬件断电后的绝对持久性。
- **个人数据的真正删除/保留政策属于第 12 和第 13 模块。** 本地草稿文件一旦被用户导出，网站无法从用户个人设备远程清除。
- **尚未进入生产。** 不改 main、不合并草稿 PR、不运行生产 Supabase 迁移、不产生新增付费服务。
